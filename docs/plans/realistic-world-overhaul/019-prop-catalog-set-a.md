# Plan 019: Prop catalog core and set A: seating, tables, beds (40 types)

Epic E2. Estimated turns: 60.

## Goal

Every landmark needs 40 or more distinct furniture and decor types. This plan builds the prop catalog (registration, metadata, headless-safe builders, merged meshes) and the first set of 40 well-detailed furniture types (14 seating, 14 tables, 8 beds and bedding, 4 outdoor seating). Props are code-built from the shared material library (plan 013); a later plan swaps some for CC0 Poly Haven models without changing any type name.

Conventions fixed here (plans 021 to 023, 041, 042 and every building plan rely on them; write them into a "Props" section of `docs/world-conventions.md`): every prop has its origin at the CENTRE of its floor footprint (the centre of the bounding box in x and z) with its lowest point at y 0, and its front toward +z (rotation 0, ARCHITECTURE.md 10.8); `size = [w, h, d]` is the bounding box of the real geometry; `topY` is the height of the main usable surface (seat, tabletop, mattress top; default `size[1]`); `mount` is `floor` (default), `wall` or `ceiling`: wall and ceiling props keep the same origin rule (centre of their footprint in x and z) but their geometry sits at its real mounting height, `size` includes that height and the bounding-box-on-the-floor check is skipped for them; `seats` are prop-local `{ x, y, z, yaw }` (`y` = the seat surface, `yaw` = the direction the sitter faces in the rotation convention, 0 = toward +z).

### Step 1: Catalog core, builder helpers, finishProp and the props fixture

Deliver:
- `tests/unit/props/catalog.test.js` first. `src/world/props/catalog.js` (headless: no `document`, no WebGL at import or build time; materials fall back to flat colours in Node) exports `registerProp(type, { category, tags = [], size, solid = true, seats = [], topY, mount = "floor", variants = 1, meta = {}, build })`: `type` matches `/^[a-z][a-z0-9-]*$/` (else throws), a duplicate throws, `size` is `[w, h, d]` (positive numbers, else throws), `build(ctx)` is required. `meta` is a free object (plan 022 adds `lightSockets`, `animated`, `textSlots`, `parts`): `buildProp` copies its keys onto `userData` (core fields win) and also keeps `userData.meta`. Also `propExists(type)`, `getPropMeta(type)` returning `{ type, category, tags, size, solid, seats, topY (default size[1]), mount, variants, meta }`, `listPropTypes()` (sorted), `listByCategory(category)` (sorted; unknown category returns an empty array) and `materialNameOf(material)` (the name remembered for a material instance made through `ctx.m`, or null; used by tests).
- `buildProp(type, { rng, tint, variant = 0, tier, rawParts = false } = {})` returns an `Object3D` (a `Group`) with `userData = { propType, size, solid, seats, topY, mount, ...meta }`; an unknown type throws. `rng` defaults to `createRng(1337)` from `src/util/rng.js` (mulberry32, plan 003); `variant` is an integer 0..variants-1 (taken modulo `variants`) that selects a preset colour or size variant, and the same variant always gives identical geometry; `tint` is a hex string that recolours only upholstery materials (it is passed to `getMaterial` through `ctx.fabric`); `tier` low removes every mesh whose name starts with `detail-` before merging (every other tier keeps them); `rawParts: true` skips `finishProp` and returns the unmerged tree (used by tests only).
- `ctx` handed to `build`: `{ root, rng, tint, variant, tier, m(name, opts?), fabric(name = "fabric"), pick(list), group(name, x, y, z, parent?), box, cyl, sphere, rbox }`. `m` is `getMaterial` and remembers each material instance together with its name in a module level `WeakMap` so `finishProp` can find its `metersPerTile` (`MATERIAL_SPECS[name].metersPerTile`, 1 when unknown); `fabric(name)` is `m(name, { tint })` when a tint was given; `pick(list)` returns `list[variant % list.length]`. Shape helpers (`x, y, z` are the CENTRE of the shape in prop-local metres, y up from the floor; they add the mesh to `opts.parent ?? root` and return it): `box(w, h, d, x, y, z, material, opts?)`, `cyl(rTop, rBottom, h, x, y, z, material, opts?)`, `sphere(r, x, y, z, material, opts?)`, `rbox(w, h, d, radius, x, y, z, material, opts?)` (RoundedBoxGeometry, 3 segments). `opts` is `{ rx, ry, rz, segments, name, color }`: Euler rotation in radians (order YXZ), radial or width segments (default 16, rbox 3), the mesh name (use `detail-<name>` for parts that low tier may drop and `keep-<name>` for parts that must stay unmerged), and `color` (hex string, written as a vertex colour attribute; see `finishProp`). `build` may return an Object3D; otherwise `root` is used.
- `finishProp(root, { tier } = {})`: (1) applies the tier rule; (2) leaves untouched every node whose name starts with `hand-` or `keep-` or is exactly `blades` (animated or movable parts used by plans 022 and 023; their local transforms stay as built and their children are not merged); (3) bakes the transform of every other mesh into a clone of its geometry, converts every geometry to non-indexed and keeps only `position`, `normal` (computed when missing) and `uv` (and `color` below), then ALWAYS calls `applyMetricUV(geometry, metersPerTile)` from `src/util/uv.js` with the metres per tile of its material (the primitive helpers have uv, but at the wrong scale); (4) merges all geometries that share a material into ONE mesh with `mergeGeometries` (name `merged-<material name>`), so a prop has at most one mesh per material; when any geometry of a material has a `color` attribute every geometry of that material gets one (white by default) and the merged mesh uses one cached clone of the material with `vertexColors: true` (so per-part colour needs no new material); (5) sets `castShadow` and `receiveShadow` true. There is no minimum number of meshes before merging; after `finishProp` a prop has at most 12 merged meshes (kept nodes not counted) and at most one mesh per material.
- `src/world/props/index.js` imports every set file (side-effect registration); `src/world/props/sets/` holds the set files. EVERY set file exports `TYPES` (the array of type names it registers) so tests can compare. `src/dev/fixtures/props.js` (register as `props`, add the import to `src/dev/fixtures/index.js`): lays every registered type on a grid, 3 m between neighbours, 8 per row (wrapping to the next row), one block per category in this order: seating, tables, beds, outdoor (then any later category in sorted order); block `k` starts at row index `r0` where each block takes `ceil(count / 8)` rows plus one empty row; row `r` is at z = `-3 * r`, column `c` at x = `3 * c`; each placed prop is built with `buildProp(type)` and pushed to `game.fixtureObjects` as `{ type, name: type, x, z }` (the array is created in `src/state.js` as `fixtureObjects: []` by plan 013; create it there if missing; `listObjects()` returns it). Spawn (10.5, 0, 12) yaw 0. The fixture logs nothing.
- Generic data-driven test `tests/unit/props/allProps.test.js` (written now, it keeps covering later sets automatically). First it reads `src/world/props/sets/*.js` with `fs`, imports each, and asserts that `listPropTypes()` after importing `src/world/props/index.js` equals the sorted union of their `TYPES` exports (so a set that `index.js` forgets to import fails). Then for every `listPropTypes()` entry: `buildProp` returns an `Object3D`; at least one mesh; no NaN in positions; after `finishProp` at most 12 merged meshes and at most one mesh per material; `rawParts: true` has at least 3 meshes (a believable prop has several parts); bounding box height and the larger footprint sides are each within 20 percent of the declared `size`; for `mount` floor: bbox min y within 0.02 of 0 and bbox centre x and z within 0.05 of 0 (origin at the floor centre); every seat lies inside the bounding box expanded by 1e-3; `userData.topY` is at most the bbox top plus 0.02, and for types that declare `topY` a downward ray (Three `Raycaster`, from y = bbox top + 1 at the first seat x, z or at (0, 0)) hits a mesh at a y within 0.03 of `topY`; `solid` is a boolean; building twice with different seeds gives the same size; building the same variant twice gives identical vertex positions (compare the sums of all position arrays); `tier: "low"` never has more triangles than high; names unique. A type that fails explains itself with its name in the assertion message.
- `tests/unit/props/catalog.test.js` covers: duplicate, bad name and bad size throw; `propExists`, `getPropMeta` shape (including `topY` default and `mount` default), `listPropTypes` sorted, `listByCategory`, unknown type throws; `meta` keys land on `userData`; and `finishProp` on a synthetic prop built with two materials (three boxes, one `detail-x` box, one `hand-test` pivot with a child, one `keep-y` box): two merged meshes, transforms baked (bounding box unchanged), the `detail-x` box gone at tier low and present otherwise, `hand-test` and `keep-y` still present and unmerged with their local transforms, `uv` u range of a 2 m wide box equals `2 / metersPerTile` of its material, a `color` option yields a `vertexColors` clone and still one mesh per source material, an empty prop does not throw. A fixture test in the same file: `registerFixture`-built `props` fixture (headless, with a fake `game`) places one object per registered type with unique x, z pairs and `fixtureObjects` filled.
