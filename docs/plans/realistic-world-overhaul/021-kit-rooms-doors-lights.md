# Plan 021: Building kit part 2: walk graph, object placement, doors, lights, lifts and the BuildingInstance

Epic E2. Estimated turns: 60. Model: opus.

## Goal

Complete the kit: a generic walk graph (reachability with the real collision world), automatic and explicit object placement from the manifest with overlap and door-clearance checks, doors built from manifest entries (plan 017), lights registered with the light manager (plan 012), lifts (plan 018), a reusable headless context, and the single entry point `buildBuilding(manifest, ctx, placement)` returning a `BuildingInstance` that can show or hide its interior. Two fixtures prove it in the browser: `cottage` (rooms, doors, lights, switch, read object, seat) and `twoStoreyLift` (stairs plus a lift).

Conventions fixed here (later plans 024 to 027 and 041 to 057 rely on them; they are also written into `docs/building-manifest.md` and appended by the plan writer to ARCHITECTURE.md 10.8): (1) `x`, `z` of lights, objects, interactables, stairs and lifts are building-local (origin = footprint centre, before the placement transform); `y` of lights, objects and interactables is measured from the floor surface of the room they belong to (`floors[room.floor].y`), never from the building origin; (2) placement transform: a local point `(lx, lz)` goes to world `(px + lx*cos(r) + lz*sin(r), pz - lx*sin(r) + lz*cos(r))` with `r = placement.rot` (Three.js `rotation.y`), `y_world = placement.y + floor.y + y`, and every item rotation, door yaw and seat yaw gets `+ placement.rot`; (3) ids: everything the kit creates is prefixed with the building id: colliders `<id>:wall:<n>` (plan 020), `<id>:prop:<n>`, door ids `<id>:<doorId>` (plan 017 then names the collider and interactable `door:<id>:<doorId>`), lights `<id>:<lightId>`, lifts `<id>:<liftId>`, interactables `<id>:<interactableId>`; (4) optional manifest fields added here: interactable `group` (switch), `object` (sit: a prop type in the same room), `readZone` (read: zone id for `openDialogue`, default the building id); door `hinge` (`left` default | `right`); object entry `variants` (integer, per-item seeded variant); (5) a prop may declare `meta.mount: "wall" | "ceiling"` (plan 022 registers it; default floor) and `meta.topY`: wall and ceiling mounted props are always `solid: false` and are never given colliders.

### Step 1: Walk graph (reachability with the real movement rules)

Deliver:
- `tests/unit/nav/walkGraph.test.js` first. `src/systems/nav/walkGraph.js` exports `reachableFrom(world, start, opts)`, `canReach(world, from, to, opts)` and `findPath(world, from, to, opts)`. `start`, `from`, `to` are `{ x, z, y }` (y is required: it selects the floor). `opts = { cell = 0.25, radius = 0.35, height = 1.7, stepUp = 0.45, bounds, maxStates = 400000 }`; `bounds = [x0, z0, x1, z1]` is REQUIRED (throw `Error("walk graph needs bounds")` when missing) and limits the search so it cannot flood the whole island.
- `reachableFrom`: breadth-first search over states `(ix, iz, yq)` where `ix = round(x / cell)`, `iz = round(z / cell)` and `yq = round(y * 10)` (ground height in 0.1 m). From each state try the 8 neighbours with `world.moveCircle({ x, y, z }, { dx, dz }, radius, { stepUp, height })` (cell centre to neighbour centre); a move is allowed when `blocked` is false and the returned position is within 0.05 m of the target cell centre horizontally; the new state takes its `y` from the result. When the number of visited states exceeds `maxStates` throw `Error("walk graph exceeded maxStates")` (exact text; tests match it). Returns `{ has(x, z, y), cells, states }`: `cells` is the number of distinct `(ix, iz)` reached, `states` the number of visited states (both plain numbers); `has(x, z, y)` is true when the cell of `(x, z)` was reached at some `yq` with `|yq / 10 - y| <= 0.3`.
- `canReach(world, from, to, opts)` runs `reachableFrom(from)` and returns `has(to.x, to.z, to.y)` (boolean). `findPath(world, from, to, opts)`: A* over the same states and moves with the Euclidean distance as heuristic and a cost equal to the move length; returns an array of `{ x, z, y }` waypoints (first = `from` cell, last = `to` cell) or `null` when unreachable. After A* the path is string-pulled with `world.raycast2D`, but only between nodes of equal `yq` (a segment is never shortened across a height change): nodes where `yq` changes (stairs, lift cabin) are kept as waypoints. A waypoint list never crosses a wall (`raycast2D` between consecutive waypoints at the same y returns no hit).
- Tests on a hand-built `CollisionWorld`: open field reachable (`cells` equals the expected count for the bounds); a wall splits two areas (`canReach` false, `findPath` null); a gap of 0.6 m is not passable but 1.2 m is; stairs (use `addStair`, rise 3.4 over run 6.8) connect two floors (the top is reached: `has(x, z, 3.4)`) and a point above the stair at `y` 0 is not reached; a disabled box (open door) connects the rooms; `maxStates: 50` on an open field throws a message containing `walk graph exceeded maxStates`; missing `bounds` throws; `findPath` waypoints never cross a wall and keep the stair waypoints (some waypoint has a different `y` than the start).

### Step 2: Object placement

Deliver:
- `tests/unit/kit/place.test.js` first. `src/world/kit/place.js` exports `placeObjects(room, manifest, { getMeta, rng })` returning `{ items, problems }`. `getMeta(type)` returns `{ size: [w, h, d], solid, topY = size[1], mount = "floor" }` (the real `getPropMeta` of plan 019 plus the `meta` fields of plan 022; a missing type makes `getMeta` throw, the placer catches it and reports `unknown-type`). `rng` is the seeded `rng()` (returns a number in [0, 1)) of `src/util/rng.js`: it is used ONLY to pick a `variant` for entries that declare `variants: n` (variant = `floor(rng() * n)`, every other item has variant 0 and consumes no random numbers). An item is `{ type, x, y, z, rot, room, variant, on? }` in building-local metres with `y` relative to the room floor (convention 1 above). Objects are processed in manifest order, except that all `on:` entries are resolved last.
- Compass and rotation (ARCHITECTURE 10.8): N = -z, S = +z, E = +x, W = -x; front of a prop at `rot` is `(sin rot, cos rot)`. Rules: (a) `wall:N|E|S|W`: the prop stands against that wall of the room with its back to it and its front into the room: N `rot` 0 with `z = z0 + d/2 + 0.05`; S `rot` PI with `z = z1 - d/2 - 0.05`; E `rot` -PI/2 with `x = x1 - d/2 - 0.05`; W `rot` PI/2 with `x = x0 + d/2 + 0.05` (`d` = `size[2]`; the along-wall position uses `w` = `size[0]`). Free segments of a wall: the wall interval inset 0.05 m at both room corners, minus every door opening that touches the room (any door whose `from` or `to` is this room and whose centre lies on this wall line) widened by 0.5 m each side, minus every window opening widened by 0.2 m each side but only for props taller than the window `sill`. All items of one wall (all entries with that `place`, expanded by `count`, in manifest order) are laid on the concatenation of the free segments (total length L, in increasing coordinate order): item i of N has its centre at virtual coordinate `L * (i + 0.5) / N`, mapped back to the real position; the whole footprint of an item (centre +- w/2) must lie inside one segment, otherwise report `wall-fit`. (b) `corner:NE|NW|SE|SW`: N = z0 side, E = x1 side; offsets `x = x1 - (w/2 + 0.05)` (or `x0 + w/2 + 0.05`), `z = z0 + (d/2 + 0.05)` (or `z1 - ...`); `rot = atan2(cx - x, cz - z)` so the front points at the room centre `(cx, cz)`; `count` above 1 for a corner reports `corner-count`. (c) `center`: the room centre, `rot` 0; with `count` n the copies are laid in a row along +x, spaced `w + 0.45`, centred. (d) `grid:RxC`: R rows along z, C columns along x, pitch `w + 0.45` along x and `d + 0.45` along z, the whole block centred in the room, items numbered row-major from the NW corner (row 0 = north, column 0 = west); `count` below R*C places only the first `count` items, above reports `grid-count`. (e) `ceiling`: x, z = the room centre (copies laid along +x as in `center`); `y` = ceiling height minus 3.0 for props with `mount: "ceiling"` (they are modelled for a 3.0 m ceiling, plan 022) and minus `size[1]` for any other prop; the ceiling height is `floors[room.floor].height`. (f) `on:<type>`: one item per item of that type in the same room (`count` items per target, laid along the target local x axis, spaced `w + 0.05`, centred on the target); `x`, `z`, `rot` of the target, `y = target.y + target.topY`; no target in the room reports `on-missing`. (g) explicit `x`, `z`, `rot`, `y` win over `place` (rot default 0, y default 0); `count` above 1 puts copies offset along +x by `w + 0.05` each.
- Problems (never silently fixed), each `{ rule, message, room, type }` with `rule` one of `unknown-type | out-of-bounds | overlap | door-clearance | wall-fit | corner-count | grid-count | on-missing`: footprints are the axis-aligned bounding box of the rotated size (`w' = |w cos r| + |d sin r|`, `d' = |w sin r| + |d cos r|`) and only SOLID items that are not `on:` items take part; `out-of-bounds`: a solid footprint leaves the room bounds by more than 0.01 m; `overlap`: two solid footprints overlap by more than 5 percent of the smaller area; `door-clearance`: a solid footprint overlaps (any amount) the clearance rectangle of a door that touches the room: width `door.width`, depth 1.0 m on EACH side of the wall plane, centred on the door.
- The door and window opening positions come from plan 020 (`at` is the offset in metres along the wall from the wall centre, positive toward +x on N/S walls and +z on E/W walls; for exterior openings the wall is the footprint wall). Do not re-derive them: if `buildWallPlan(manifest).openings` already carries the wall letter, absolute along-wall centre and width, use it; otherwise add ONE exported helper `openingsOnWall(manifest, room, wallLetter)` to `src/world/kit/walls.js` (adding an export is allowed, change nothing else there) returning `[{ kind: "door" | "window", a, b, sill? }]` (interval along the wall in absolute building-local coordinates) and use that.
- Tests (use a fake `getMeta` table): each `place` kind gives exact coordinates and rotations for a 6 x 4 room (all four walls including rot values, four corners, center, ceiling for a `mount: "ceiling"` and a plain prop, grid 2x3 with the exact 6 centres, `on:` with `topY`, `on:` with count 2); two entries on one wall are packed in listed order and a door opening is skipped (items never overlap the door interval plus 0.5 m); a window ignored for a low prop and respected for a tall one; explicit coordinates win over `place`; `count` 3 with explicit x gives copies +w+0.05 apart; every problem rule is produced by one test (unknown-type, out-of-bounds, overlap, door-clearance, wall-fit, corner-count, grid-count, on-missing); two overlapping explicit props reported; an overlap of 3 percent is not reported; rotated 90 degrees footprints swap w and d; `variants: 3` with the same seed gives identical variants twice and uses values 0..2; without `variants` the rng is never called (spy); deterministic output for the same seed.
