# Plan 026: Grand Hotel ground floor: lobby, restaurant, kitchen, stair hall

Epic E2. Estimated turns: 60.

## Goal

Furnish and light the four public rooms of the hotel (`lobby`, `restaurant`, `kitchen`, `stairhall`) by data only: object lists, lights, switches, seats and a `read` object at the reception desk (A6), all written into `src/world/buildings/plaza/manifest.json`, plus ONE new prop type (`reception-desk`, new set file `src/world/props/sets/hotelLobby.js`) and three sign keys. Plan 024 fixed the structure (rooms, doors, windows, stairs, the lift `lift1`); this plan never changes bounds, floors, doors, windows, stairs or lifts, and never edits plan 023 files (`hotelRoom.js` stays as it is). Minimums of distinct object types: lobby 18, restaurant 18, kitchen 16, stairhall 12; the manifest declares them in its own `roomMin` so the flag-less `check:buildings` run enforces them (plan 024 mechanism).

Rules used below (plan 021; ARCHITECTURE 10.8): all coordinates are building-local metres (origin = footprint centre, x in [-14, 14], z in [-10, 10], front of the hotel = +z), `y` of anything is above the floor of its room, rotations `rot` in radians (front of an object at `rot` = `(sin rot, cos rot)`: 0 faces +z/south, 3.1416 faces -z/north, 1.5708 faces +x/east, -1.5708 faces -x/west). Notation for object entries: `type (x, z, rot)` is `{ "type": ..., "x": ..., "z": ..., "rot": ... }`; `y 0.8` adds `"y": 0.8` (ceiling-mounted props are modelled for a 3.0 m ceiling and the ground floor ceiling is 3.8 m, so they get y 0.8); `type wall:N xK` is `{ "type": ..., "place": "wall:N", "count": K }` (the placer packs all entries with the same wall letter in manifest order); `type on:<target> xK` is `place: "on:<target>"` with `count` K per target; `type at:window:<id>` and `type at:door:<id>` are `place: "window:<id>"` / `place: "door:<id>"`; `text` is the optional `text` field (a sign key). Wall contact rule used for every explicit wall coordinate: back of the object `0.05 m` from the inner wall face, inner face = room bound moved inward by 0.3 m on perimeter walls (footprint edge) and by 0.075 m on partitions. If `checkBuilding` or the build reports a placement problem for a coordinate below (overlap, out-of-bounds, door-clearance, wall-fit), move or shrink THAT entry by the smallest amount (a different x or z, a smaller count); never weaken the check, never drop a type below its room minimum, never change the structure.
