# Plan 064: Audio core: sound bank, event sounds and footsteps by surface

Epic E6. Estimated turns: 75.

## Goal

Rebuild the audio layer around three ideas: a sound bank (every sound id resolves to files or to a generated silent fallback), a footstep system that picks the sound from the surface under the player (grass, sand, gravel, wood, tile, carpet, stone, metal), and event sounds for doors, switches, sitting, lifts, interaction, typing and pick-up. All new sounds are generated by `scripts/assets/synthSfx.mjs` (no other audio host is reachable, ARCHITECTURE.md 10.1), CC0 in the ledger. This plan owns the audio engine (`src/systems/audio/engine.js`) and the sound bank (`src/systems/audio/bank.js`); plan 065 adds acoustics and ambience on top of them, plan 066 adds the music module and the settings sliders. A test fails if any surface value used by a manifest or by the island lookup is not mapped to one of the 8 footstep surfaces.

New one-shot recipes: `footstep_<surface>_1`, `footstep_<surface>_2`, `footstep_<surface>_3` for each of `grass` (soft swish and thud), `sand` (crunchy hiss), `gravel` (crunchy stones, longer), `wood` (hollow knock with a short resonance), `tile` (sharp click with a little ring), `carpet` (very soft muffled thud), `stone` (hard tap with a short echo), `metal` (ringing clang, short): 24 recipes, each 0.12 to 0.3 s. Also `door_open` (latch click then thump, 0.6 s), `door_close` (0.5 s), `door_locked` (rattle, 0.4 s), `switch_click` (0.12 s), `sit` (cushion thump, 0.5 s), `stand` (small rustle, 0.4 s), `lift_ding` (two-tone bell, 1.0 s), `typing_tick` (soft click, 0.12 s), `pickup` (soft chime, 0.25 s), `step_water` (wading splash, 0.3 s, used by the footsteps). `splash_rain` is NOT made by this plan: plan 062 plays it and runs before 064, so 062 must add it to `RECIPES` (cross-plan request; 064 does not list it). Seamless loop method: the last 50 ms are equal-power crossfaded into the first 50 ms before the WAV is written. Seeds: every recipe and loop is rendered with `renderRecipe(name, seed)` (which looks up both `RECIPES` and `LOOPS`, so `lift_move` renders by name) where `seed` is the 32-bit FNV-1a hash of its full name (for example `footstep_grass_2`), so the three variants differ and reruns are identical.

- `src/systems/audio/bank.js`: `SOUNDS` maps each id to `{ files: [url, ...], volume, loop, pool, fallback }`. `files` are URLs under `/audio/sfx/` built from the app base URL (publicDir is `assets/`; the URL must respect the `/portfolio/` base, and the test checks it); `pool` is the maximum number of simultaneous instances (default 6); `fallback` is the name of an in-memory silent buffer (0.1 s of zeros) used only when a file fails to load (it is not a second file on disk). `resolve(id)` returns the file urls and throws for an id that is not in `SOUNDS`. - `src/systems/audio/engine.js` (headless testable; Howler is injected so the unit test can fake it): (a) unlock: the first `keydown` (any key, Shift included) or the first `pointerdown` unlocks audio (Howler unlock and resume); `unlocked` becomes true on that gesture even when the context stays suspended. ### Step 3: Footsteps and event sounds, Playwright

Deliver:
- `src/systems/audio/footsteps.js`: `FootstepSystem.update(dtMs, player)` (dtMs is the frame dt from the game loop, which keeps running under `?freeze=1`; see plan 065). Player fields used (all named here): `grounded`, `airborne` (= not grounded) and `speed` (horizontal metres per second) and `sprinting` (plan 016 controller; sprint is 7.8 m/s, walk 4.0 m/s, ARCHITECTURE.md 10.4); `sitting` (plan 018); `inLift` (the flag plan 020 sets on the player, `player.inLift`, while it rides a lift cabin); `x`, `y`, `z` (plan 016). Steps are counted by DISTANCE only: when `grounded`, not `sitting`, not `inLift` and `speed` is over 0.3 m/s, add `speed * dtMs / 1000` to `distance`; each time `distance` reaches 0.62 m, play one step and subtract 0.62 m (the remainder is kept). The cadence derives from speed (about 0.16 s per step at walk speed and 0.08 s at sprint speed). Volume 0.25 walking and 0.4 sprinting. The rate is `1 + (r - 0.5) * 0.2` (range 0.9 to 1.1) with `r` from the seeded RNG (plan 003, seed from `?seed=`, default 1337). Variants rotate round-robin 1, 2, 3 per surface (deterministic; never the same variant twice in a row).
- Surface for a step, in this order: (1) inside a building room: `player.insideRoom` (the room id from plan 021 `insideRoom()`, or `<bldId>:<roomId>`); `resolveRoom(buildings, insideRoom)` (helper of step 2) gives the `surface` of that room; if that surface normalizes to `metal` the step is metal (this covers stairs in a metal room); (2) on the jetty: the point lies inside the rotated rectangle of `harbour.jetty` (town.json: start `x, z` on the quay edge, direction `(sin rot, cos rot)`, `length` 55, `width` 4, plan 032) gives `wood`; (3) wading: `depth = WATER_LEVEL - heightAt(x, z)` with `WATER_LEVEL` -1.2 m (ARCHITECTURE.md 10.4) and `heightAt` from plan 033: when `0 < depth < 0.6` the surface is `sand` and each step also plays `step_water`; `depth >= 0.6` is swimming and makes no steps; (4) otherwise `surfaceAt(x, z)` from plan 034 (grass, sand, gravel or stone). Any surface value that fails `normalizeSurface` falls back to `stone` at runtime and the test in step 2 catches it. Each step sets `lastFootstep = { surface, file, t }`.
