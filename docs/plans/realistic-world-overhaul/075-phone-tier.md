## Steps

Do the steps in order. After each step run the checkpoint command from your prompt and continue only on `CHECKPOINT <n> OK`.

### Step 1: Decor halving and lazy interiors in the kit

Deliver:
- `tests/unit/kit/phoneTier.test.js` first. Add a boolean `decor` to prop metadata (set it on the clearly optional types in the catalog by editing the set files: rugs, pictures, vases, plants, cushions, books, plates and glasses, plaques, banners, flowers, small signs, bunting; never on furniture people sit at, beds, tables, counters, machines, doors, stairs, lifts, interactable objects or anything with `seats`). `placeObjects` takes `{ decorScale }` and drops decor items deterministically (by a hash of building id, type and index) so that on `decorScale` 0.5 about half of the decor items remain (45 to 55 percent) and no required interactable object, seat, door-adjacent item or `read` target is dropped; solid furniture is never dropped.
- `BuildingInstance.ensureInterior()` and `releaseInterior()`: when `TIER_SETTINGS[tier].interiorsOnEntry` is true the manifest props, interior meshes and lights are built only when the player is within 14 m of an exterior door or inside, and released (geometry and light registrations disposed, colliders of props removed, shell colliders and doors kept) when the player is farther than 45 m, with at most one build per frame slice and a 3 s cooldown against flapping. On `high` the interiors stay built while the area is loaded. Textures are shared through `getMaterial`, so releasing does not thrash.
- A per-building GPU memory cap: `estimateBuildingMemory(instance)` (triangles times 36 bytes plus texture bytes of unique textures) and `TIER_SETTINGS.low.buildingMemoryMb = 18`; when the sum over built interiors exceeds the cap the farthest interior is released first. Tests: decor drop ratios for 3 sample manifests (the hotel lobby, the library, a house) within 45 to 55 percent of decor items on low and 100 percent on high; none of the protected categories is ever dropped; interiors are not built when the player is 60 m away on low and are built within 14 m; release order is farthest-first; the memory cap is respected in a simulated visit of all 14 buildings; no placement problems are introduced by dropping items.

Check for this step (the runner runs it too; it fails before the work and passes after):

- `node "{{runner}}/assert.mjs" has src/world/kit/building.js "ensureInterior"`

### Step 2: Phone budgets and the first-session download

Deliver:
- `src/preload.json`: the list of files the first session needs on a phone (center and hotel areas, the 512 textures for their materials, the avatar, fonts, the music and sound files for the start, the code chunks); it is generated by `scripts/make-preload.mjs` from a Playwright run that records every response URL from page start to `__world.ready` at the phone viewport with `?quality=low`, and the unit test checks that the list is not stale (every file exists).
- `tests/e2e/phone-download.spec.js` (journey 7, second half): a context at 390 by 844 with `hasTouch` and `isMobile`; record `response` events and their body sizes from navigation until `__world.ready`; assert the total decoded body bytes are under 25 MB (25 * 1024 * 1024) and print the top 10 files; assert no GLB prop (hero props are skipped on low), no 1k or 2k texture and no `amb_*` loop larger than 600 KB is fetched before ready; assert `listLights()` has no pooled light; `rendererInfo().calls` at the spawn is at most 250 and triangles at most 800000; `quality()` is `low`.
- Run `npm run check:budget`: the phone profile must pass at every spot of `src/budgets.json` (all landmarks, square, harbour, beach, forest). Fix the heaviest spots with the tools you have: fewer decor items (the `decor` flag), merging, instancing, lower vegetation density, hidden interiors, shadow settings; never raise a limit. Record the final numbers in `docs/perf/phone-final.json`.
- Reduce first-load size if the test fails: smaller music (the start only needs one track: load the other tracks lazily after ready), lazy-load ambience loops after ready, defer the credits and text-mode code, drop unused 2k textures from the low path. Keep a list of what you moved in the report.
